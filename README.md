# KOGAMA ARCHIVE

> Независимый цифровой архив о KoGaMa: посещаемость, популярность и история платформы.

**Навигация:** [Цель](#цель-проекта) · [Возможности](#возможности) · [Источники данных](#источники-данных) · [Технологии](#технологии) · [Структура](#структура-проекта) · [Обновление статистики](#обновление-статистики) · [Обновление сайта](#обновление-сайта-и-кэширование) · [Ограничения](#ограничения-и-достоверность) · [Планы](#планы-развития)

## О проекте

KOGAMA ARCHIVE — статический сайт на GitHub Pages. Он хранит замеры месячной посещаемости kogama.com, хронологию событий и пояснения о происхождении данных, чтобы будущие посетители могли увидеть, как менялась популярность платформы.

## Цель проекта

Сохранить информацию о KoGaMa и задокументировать изменения её популярности во времени. Проект оставляет исторический след: через годы по нему можно будет изучать, какой платформа была раньше и как менялась.

## Возможности

Реализовано:

- **Исторический график посещаемости** с выбором периода, подсказками и отметками источника точек.
- **Архив статистических данных** — `data/traffic.json`, одна точка на календарный месяц.
- **Сравнение двух периодов** (год или месяц) со средним значением и процентным изменением.
- **Аналитика**: средние по годам и месяцам, максимумы и минимумы среди собранных замеров, самые заметные изменения, периоды устойчивого роста и снижения (три изменения подряд). При нехватке данных сайт прямо сообщает об этом.
- **Историческая хроника** со статусами достоверности и источниками.
- **Источники и достоверность** — пять категорий данных.
- **Журнал изменений** — версия сайта, дата обновления сайта, дата проверки статистики и дата изменения значений.
- **PWA**: Service Worker, автоматическое получение новых версий, работа офлайн на последней сохранённой версии.

В разработке / планируется: см. [Планы развития](#планы-развития).

## Источники данных

Статистика берётся с HypeStat, а часть исторических точек может быть получена из снимков Wayback Machine.

> **Данные HypeStat являются оценкой стороннего сервиса и не представляют собой официальную статистику KoGaMa.**

Сайт различает категории: официально подтверждённые сведения; данные сторонних сервисов; архивные материалы; приблизительные исторические оценки; предположения и аналитические интерпретации. Подробнее — в разделе «Источники» на сайте.

«Исторический максимум» на сайте означает максимум среди реально собранных замеров, а не за всю историю KoGaMa.

## Технологии

- HTML, CSS, JavaScript (без фреймворков и внешних библиотек; график — SVG, рисуется кодом проекта)
- JSON для данных
- GitHub Pages — хостинг
- GitHub Actions — ежедневная проверка источника и проставление версии ресурсов
- PWA: `manifest.json` и Service Worker
- Node.js (без зависимостей) — скрипты сбора и проверки

## Обновление статистики

Workflow `update-traffic.yml` запускается ежедневно (и вручную). Скрипт читает страницу HypeStat и сохраняет не более одной точки на месяц. Если разметка источника изменилась или данные не разобрались, запуск завершается ошибкой, а старые данные остаются нетронутыми. Если значение не изменилось, точка не меняется.

Три разные даты в `meta.json` и в журнале нельзя путать: **проверка источника** ≠ **изменение значений** ≠ **обновление сайта**. Дата проверки записывается не чаще раза в неделю, чтобы не создавать ежедневные коммиты. Токены и секреты в репозитории не хранятся.

## Обновление сайта и кэширование

Раньше страница и ресурсы отдавались из кэша Service Worker по принципу «сначала кэш», а имя кэша менялось вручную, поэтому новая версия могла не доходить до пользователей без `Ctrl+Shift+R`. Теперь:

- `scripts/stamp-version.js` считает хеш содержимого сайта и подставляет его в `?v=` для CSS и JS, в `sw.js` и в `version.json`.
- Любое изменение ресурсов меняет `sw.js`, браузер устанавливает новую версию целиком и страница перезагружается автоматически (не чаще раза в 30 с).
- HTML и JSON-данные запрашиваются сначала из сети с ревалидацией; без сети используется последняя сохранённая копия.
- Если установка новой версии не удалась, остаётся прежняя рабочая.

**Перед публикацией** выполните `node scripts/stamp-version.js` и `node scripts/check.js`. Если забыть, `stamp-version.yml` проставит версию автоматически после пуша.

## Ограничения и достоверность

- Исторические данные неполны: замеры начинаются с даты первого сохранённого значения и могут иметь пропуски.
- Оценки сторонних сервисов не гарантируют точности.
- Аналитика — это расчёты по имеющимся замерам, а не прогноз и не объяснение причин.
- События без документального источника помечены как «Не подтверждено». Сведения о KoGaMa Space пока не подтверждены.

## Авторство и независимость

KOGAMA ARCHIVE — независимый неофициальный проект. Он не связан с разработчиками и владельцами KoGaMa и не претендует на принадлежность к ним. Имя автора, контакты и лицензия в репозитории не указаны.

- Дополнить хронику и сведения о KoGaMa Space при появлении проверяемых источников.
