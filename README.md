## О проекте

KoGaMa — это не только игровая платформа, но и часть истории интернет-сообщества. KOGAMA ARCHIVE создан для сохранения этой истории: проект документирует изменения популярности платформы, собирает доступную статистику, архивные материалы и важные события. Его цель — сохранить информацию о KoGaMa для нынешних и будущих поколений пользователей.

## Цель создания архива

Оставить исторический след, по которому через 5–10 лет можно будет изучать, какой была платформа, как менялась её популярность и что происходило вокруг неё.

## История и концепция

Проект начался как график месячной посещаемости kogama.com и развивается в сторону цифрового музея: статистика + хронология + галерея + документы + прозрачные источники. Принцип: **достоверность важнее наполненности**. Чего мы не знаем, того не придумываем; пустые разделы честно показывают «Архив пополняется».

## Основные возможности

Реализовано (в коде и данных):

- **Главная** — вводная страница; счётчики на ней считаются из реальных данных.
- **Статистика** — текущее значение, карточки показателей, график с периодами, качественная заглушка до появления данных.
- **История** — вертикальная хронология карточками: дата или год, описание, источники, раскрывающиеся подробности; статусы «Подтверждено», «Частично подтверждено», «Не подтверждено» и отметка «Приблизительная дата».
- **Галерея** — карточки, фильтры по году и категории, ленивая загрузка, просмотр изображения с подписью и источником. **Сейчас в галерее нет ни одного изображения**: реальные материалы нужно добавить (см. [Как обновлять данные](#как-обновлять-данные)).
- **Тогда и сейчас** — сопоставление двух годов по событиям и статистике; переключатель «до/после» для изображений заработает после добавления пар в `data/compare.json` (сейчас пусто).
- **Аналитика** — сравнение двух периодов, средние по месяцам и годам, максимумы и минимумы среди собранных замеров, самые заметные изменения, периоды устойчивого роста/снижения. При нехватке данных показывается соответствующее сообщение.
- **Источники** — пять категорий достоверности, предупреждение о HypeStat, документы и материалы (сейчас пусто), сообщества (сейчас пусто), «Предложить материал» через GitHub Issues.
- **Журнал** — версия сайта, дата обновления сайта, дата проверки источника, дата изменения значений.
- **PWA** — установка, офлайн-работа, автоматическое обновление.

## Источники данных

Посещаемость берётся с HypeStat; часть исторических точек может быть получена из снимков Wayback Machine (скрипт `scripts/backfill-wayback.js`, запускается вручную; на момент написания импорт не выполнялся).

> Данные HypeStat являются оценкой стороннего сервиса и не представляют собой официальную статистику KoGaMa.

События хроники подкреплены ссылками там, где источник найден (объявление на kogama.com, отчёты Adventure Box Technology AB). События без источника помечены «Не подтверждено».

## Достоверность информации

Сайт различает: официально подтверждённые сведения; данные сторонних сервисов; архивные материалы; приблизительные исторические оценки; предположения и аналитические интерпретации. «Исторический максимум» — максимум среди реально собранных замеров, а не за всю историю KoGaMa. Данные могут быть неполными, оценки сторонних сервисов не гарантируют точности. Сведения о KoGaMa Space пока не подтверждены.

## Используемые технологии

HTML, CSS, JavaScript (без фреймворков и внешних библиотек; график — SVG), JSON, GitHub Pages, GitHub Actions, Service Worker и Web App Manifest, Node.js (скрипты без зависимостей). Шрифты загружаются с Google Fonts; без сети используются системные.

## Автоматическое обновление статистики

Скрипт `fetch-traffic.js` читает страницу HypeStat и хранит не более одной точки на календарный месяц. Если разметка источника изменилась, запуск завершается ошибкой, а прежние данные остаются. Три даты нельзя путать: **обновление сайта** ≠ **проверка источника** (`meta.lastChecked`, пишется не чаще раза в неделю) ≠ **изменение значений** (`meta.lastValueUpdated`). Успешный запуск Actions не означает, что статистика изменилась.

## GitHub Actions

- `update-traffic.yml` — ежедневно в 05:17 UTC и вручную: сбор данных и коммит при изменениях.
- `stamp-version.yml` — при изменении файлов сайта проставляет версию ресурсов и запускает `scripts/check.js`.

Секреты и токены в репозитории не хранятся (используется встроенный `GITHUB_TOKEN`).

## PWA и Service Worker

- CSS и JS подключаются как `?v=<хеш>`; хеш подставляет `stamp-version.js`. Любое изменение сайта меняет `sw.js`, и браузер устанавливает новую версию.
- Оболочка (HTML, CSS, JS) кэшируется целиком под одной версией: новая страница не получит старые CSS/JS. Если установка не удалась, остаётся прежняя версия.
- HTML и JSON запрашиваются сначала из сети (с ревалидацией, без повторной загрузки неизменённого), офлайн используется последняя копия.
- Изображения кэшируются отдельно и не скачиваются заново при выходе новой версии сайта. **Новое изображение — новое имя файла.**
- Автоматическая перезагрузка при смене версии — не чаще раза в 30 секунд и один раз на версию (защита от циклов).
- GitHub Pages отдаёт файлы с `Cache-Control: max-age=600`; поэтому запросы HTML/JSON идут с ревалидацией, а `sw.js` регистрируется с `updateViaCache: 'none'`.

## Как запустить локально

Открывать `index.html` двойным щелчком нельзя: браузер запрещает чтение JSON с `file://`, и данные не загрузятся (сайт покажет сообщение об этом). Нужен сервер:

```bash
cd kogama-archive
python -m http.server 8000   # затем http://localhost:8000
```

## Как обновлять данные

1. Изменили сайт (HTML/CSS/JS/иконки/`sw.js`) → `node scripts/stamp-version.js && node scripts/check.js`, затем коммит и пуш.
2. Событие: добавьте объект в `data/events.json` (`date`/`year`, `dateType`: `exact|year|approx`, `status`: `confirmed|partial|unverified`, `sources`).
3. Изображение: положите файл в `img/gallery/` (оптимизированный, лучше WebP/JPEG; при необходимости миниатюра) и добавьте запись в `data/gallery.json`: `title`, `image`, `date`, `source` (+`sourceUrl`), `category`, `status`, `description`. Фон главной берётся только из записи с `"hero": true` и статусом `confirmed`. Не добавляйте случайные картинки из интернета и сгенерированные изображения как исторические.
4. Документ: запись в `data/documents.json` (`title`, `desc`, `date`, `source`, `url`).
5. Запись в журнал: `data/changelog.json` (новая версия сверху).

## История изменений

См. раздел «Журнал» на сайте и `data/changelog.json`.

## Планы развития

Планируется (не реализовано): наполнение галереи, документов и сравнений реальными материалами; импорт исторических точек из Wayback Machine; уточнение сведений о KoGaMa Space при появлении проверяемых источников. Форма предложения материалов работает через GitHub Issues и требует, чтобы в репозитории были включены Issues.

## Авторство и независимость

KOGAMA ARCHIVE — независимый неофициальный проект. Не связан с разработчиками и владельцами KoGaMa. Имя автора, контакты и лицензия в репозитории не указаны.
